## 修正与拒绝范围

原接收函数在 RX_SIZE 无效时保留 ret=0，并在未读取 msg 的情况下转交 TCPM，已用实际函数离线复现。修正明确返回 -EINVAL、归还 RX 缓冲；任何确认失败均不转交消息。msg 初始化避免短消息尾部残留。真实读取的 header=0 只增加诊断，仍走 TCPM 校验，不绕过角色校验或自动伪造合约。

无效长度、读取/确认错误、真实零头报文分别记录 size/status；接收复位中断与发送复位请求分别记录方向/类型/结果，采用内核限速日志。它们进入已有 RAM 充电时间线，不能把“接收复位信号”直接等同于充电器故障。

TCPM 环形缓冲由 1024 增到 8192 条，仍有界；用户空间按相同上限导出，并报告起止、行数、读取错误/上限。移除“只打印 1024 行却继续消耗后续记录”的路径。不能承诺任意长测试均无溢出。

Windows 导出先有界接收原始字节至结束帧，再校验完整帧和连续序列、写盘；失败保留原始 partial，最终文件仍独占发布。16 MiB/超时/身份检查保留。仅改变接收处理时序，不能据离线回归保证所有 USB 缺段已经消失。

## 应用、验证与准入

构建顺序：既有 PMIC/供电集成之后执行应用器，再执行内核配置和编译。应用前核对内核 marker 与两个原文件完整哈希，全部确认后才写入；幂等重跑核对应用器、接收片段和输出哈希，源或输入变化则要求新源码目录。输出 pd-diagnostics-inputs.json 保存来源及修改后身份，L2 同时检查 PD PHY 对象和已链接 ISR。

新增实际接收函数用例遍历 RX_SIZE 0～255，覆盖各步 I/O 和确认失败、短报文尾部初始化及真实零头传递；应用器覆盖固定源、幂等、错误源不写和已应用文件漂移。日志测试覆盖 1500/8191/超上限导出和 9000 条 Windows 缓冲解析，以及损坏帧、断线、超时、容量和失败原始数据保留。

本轮 Linux 全部 116 项回归通过；Windows 补齐原生 C 编译器后，针对性 18 项全部通过、零跳过（工具链与复跑命令见本机记录）。新固件 L2 与真机状态由本机记录和 CONTEXT 维护。原中断时 RX_SIZE 未记录，已知缺陷与特定硬复位之间的因果关系仍开放；不以 L1 或扩大缓冲推断持续 PPS 已稳定，RISK-004 继续阻断发布。
