# 2026-11-10 SN100T Linux NFC/NCI 适配

## 范围与准入

RQ-14 / WP10 / TD-003、TD-007；工作分支 `codex/nfc-mainline`，基于 `5f00c534c2544ce5ca7e10c3084916cc8139521e` 的未提交工作树。Windows 11 X64 / PowerShell 7.6.9 / Python 3.14，目标 L2 在 WSL Ubuntu 24.04 / Linux x86_64 / bash，以 aarch64-linux-gnu-gcc 13.3.0、GNU make 4.3 执行。未操作手机、未改变设备供电、未提交/推送/发布或合并。

准入范围为使用 Linux NFC/NCI 的本地 SN100T transport、设备树 binding、构建闭包与最小标准枚举消费者。目标是可送上游审查的子系统实现，尚无上游合入证明。eSE、HCE、固件升级及活动 NFC 唤醒均不支持；未知驻留固件、RF 参数与共享 VEN 恢复归 RISK-011。本轮不修改有线 USB/PD/PPS、无线 RX 或无线 TX 的驱动/配置，共存策略仍分别验收。

## 接口矩阵与候选取舍

| 功能 | 固定 mainline 子系统/ABI/binding | Debian 消费者 | 本地差异与边界 |
| --- | --- | --- | --- |
| SN100T 设备发现/控制 | NFC/NCI、generic netlink NFC_CMD_GET_DEVICE | `python3 tools/nfc_inventory.py` | 专用 `nxp,sn100t` transport；不导出 `/dev/nq-nci` |
| NFC RF 数据 | NCI core、AF_NFC / NFC_SOCKPROTO_RAW | 后续固定 Linux 标准读卡工具/服务 | 协议掩码仅列测试范围；本轮无 RF/NDEF L3 或 Debian 服务 |
| GPIO/IRQ/PM | gpiod、I²C、threaded IRQ、dev_pm_ops | NFC DEV_UP/DOWN 生命周期 | VEN 不拉低；活动/故障 NFC 阻止 suspend，不实现 wake |
| 板级 DT | 本地 `net/nfc/nxp,sn100t.yaml`、enable/firmware-gpios、interrupts | 内核 OF/I²C 自动绑定 | IRQ111 高电平，VEN83、FIRM110、CLKREQ7；binding 未上游 |
| 被动救援诊断 | I²C DT/sysfs、`/sys/class/nfc` | 控制台 nfc-status | 仅元数据，类目录计数包括其他控制器，不发 NCI/RF |
| eSE/固件下载 | 无实现 | 无 | 独立评估，禁止借用 NFC 结论或硬复位恢复 |

直接套用固定 `nxp-nci` 的问题是 close 拉低 VEN、固件下载模式与共享 NFCC/eSE 不匹配，且现有 `nxp,nci.yaml` 未声明 SN100T。选择独立最小 transport，保留主线 NCI core 的 reset/init、协议与 Netlink/AF_NFC；未修改 NCI core，未冒用 PN553/NQ310 compatible。

RX 先读 3 字节头，再按长度读 0–255 字节；短读、短写、负 errno、内存分配失败停止 IRQ 并锁存故障。send 消费 skb，异常同样释放；close 在互斥锁外 synchronize_irq，避免等待 IRQ 线程死锁。NCI core 的 close 不返回 reset 错误给 transport，因此本地只观察 reset：最近 TX 必须为 CORE_RESET，成功响应后 NCI 2.x 还需请求触发的完整通知；无成功证明则锁存 ETIMEDOUT、拒绝 reopen/suspend，保留 VEN。

移植脚本在写入前检查版本、路径类型、旧文件哈希；只有已知旧缓存可清理，未知修改拒绝覆盖。来源缓存验证器仅允许对应 Kconfig/Makefile 规则；生成驱动每次从锁定项目输入重写。构建验证内建配置、对象、链接符号、DT compatible/地址/GPIO/IRQ，并拒绝旧 nqx_probe/nfc_ioctl 符号。
