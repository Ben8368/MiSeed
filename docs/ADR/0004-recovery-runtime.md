# ADR 0004：Recovery 独立用户空间与语言分工

- 状态：已接受
- 日期：2026-11-05

## 背景

补读引用调研的第五个用户回合：用户将 Recovery 纳入平台，并询问全项目语言选型。既有救援 initramfs 设计未明确其与正常系统及后续安装器的关系。

## 决策

Recovery 作为共享 Linux 内核之上的独立用户空间，拥有独立 initramfs，不复制硬件驱动树、不依赖正常 rootfs。接口与语言分工集中写入 [ARCHITECTURE](../ARCHITECTURE.md)，救援和安装行为集中写入 [RECOVERY](../RECOVERY.md)。

先实现诊断闭包；包验证与安装写入分阶段交付，安装能力不因采用 Rust 自动获得安全保证。沿用 C/上游原生构建体系，新 Recovery 核心使用 Rust，宿主编排使用 Python，Shell 保持小型。

## 后果

内核升级需要同时验证两种启动环境。当前不创建空 Cargo 工程、虚构驱动、未审查来源锁或返回成功的构建占位命令；语言选型不构成工具链已锁定或已有 L2/L3 证据。
