# ADR 0002：独立集成与分阶段构建

- 状态：已接受
- 日期：2026-11-05

## 背景

用户指定 umi、UEFI 与 Linux 6.18+，明确要求从全新仓库按功能移植多个来源，不依附单一 fork；同时希望未来有用户空间与安装包。示例文档没有体现这些需求，需建立可审查的模块接口。

## 决策

- 保持适配层定位，独立管理设备描述、补丁、构建与用户空间配方；完整上游树和发行版包来自外部固定输入。
- 以保留厂商底层启动链的第二阶段 UEFI + Linux EFI Stub 为产品目标，同时保留 Linux 独立诊断路径。
- Debian ARM64 为首选用户空间；Fastboot 与 EDL 分阶段设计，打包不等于授权写入。
- 候选清单与构建锁分离；没有确切 commit、许可证、工具链与配置的输入不参与产品构建。
- 先落地 L0/L1 CI；引入对应源码时再接线真实 L2 构建，不设空成功占位 job。

## 后果

增加来源比较、锁定和接口测试工作，但避免被单一来源目录/脚本绑定。Linux 直启成功不等于 UEFI 交接成功；来源报告、离线检查、编译与真机证据分开记录。MVP 不依赖 EDL 可用或覆盖 Android 数据。
