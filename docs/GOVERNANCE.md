# 文档治理

每类事实只有一个正文位置；其他文档至多保留一句摘要和链接。冲突时修正副本，不同步维护多份。

## 职责边界

| 文档 | 只负责 | 不承载 |
| --- | --- | --- |
| 根 AGENTS / README | AI 读取路由 / 人类开发导航 | 专题规则全文、当前进度 |
| CONTEXT | 当前阶段、最多三项优先级、最新证据链接 | 长期设计、完整任务单、日志 |
| LESSONS、lessons/ | 可复发经验索引、专题结论 | 项目状态、已有规则复述 |
| PRODUCT | 目标、需求追溯、MVP、非目标 | 技术接口、步骤、完成状态 |
| ARCHITECTURE | 模块职责、输入输出、跨层接口 | 机型参数、实现进度 |
| RECOVERY | 救援默认行为、安装/恢复状态机 | 内核驱动副本、设备布局、实现进度 |
| platforms | 设备身份、具体运行契约、硬件能力证据 | 通用架构、通用安全规则 |
| implementation-plan | 工作包依赖、交付、完成条件 | 当前进度、命令教程 |
| AI_RULES | 执行顺序、Audit、Git 授权、提交与合并规则 | 测试分级、CI 配置 |
| QUALITY | 证据等级、最低验证、风险审查要求 | 运行结果、workflow 说明 |
| CI | 工具用法、自动化覆盖/盲区、平台接线 | 验收原则、提交署名规则 |
| PROVENANCE | 来源锁定、归属、许可与分发规范 | 候选 URL 副本、硬件能力 |
| RISK_REGISTER / TECH_DEBT | 未知假设及关闭条件 / 有意妥协及偿还条件 | 同一事项的双重登记 |
| ADR/ / archive/ | 长期决定及理由 / 带日期的历史依据与证据 | 活动状态、日常必读规则 |
| templates/ | 可复用记录字段 | 已完成的证据 |

候选身份只维护在 manifests/sources.json，真正构建输入另建经审查的锁。维护者身份以托管平台记录为准；开发、复核、合并责任按 AI_RULES 与 QUALITY 分工。

## 篇幅与读取

| 范围 | 最大行数 | 最大字符数 |
| --- | ---: | ---: |
| AGENTS.md / README.md（各） | 45 | 2200 |
| CONTEXT | 25 | 1200 |
| LESSONS | 12 | 600 |
| 单篇 ADR（含索引） | 30 | 1800 |
| 其余活动 docs 文档（每篇） | 60 | 3500 |

预算由 tools/check_repo.py 检查，历史 archive 不进入默认加载预算。超限先去重、压缩或归档，不提高上限，也不为绕过预算机械拆篇。

新增文档必须有独立职责、真实使用入口且现有文件无法承载；不为单个待办、空计划或重复索引建文件。跨文档链接只导航，不触发 AI 连带读取。归档与 ADR 仅在追溯对应事实时加载。

## 更新与归档

状态词：设计中＝仅方案；计划＝已排入；已实现未验证＝代码存在；已验证＝有指定环境证据；不支持＝明确拒绝。证据等级由 QUALITY 定义。

当前状态只改 CONTEXT；风险关闭、债务偿还后移入带日期归档并留指针。ADR 追加、不改写历史，编号唯一、索引状态一致，替代须指向不同 ADR 并说明范围。背景调研只作历史依据。

文档变更依 QUALITY 验证；人工复核职责互斥与按需加载，CI 不宣称能判定语义重复。
