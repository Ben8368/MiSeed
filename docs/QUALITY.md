# 质量与验收

## 证据分级

| 等级 | 必要证据 | 不能推出 |
| --- | --- | --- |
| L0 静态 | 文本、语法、链接、策略或审查结果 | 产品可编译 |
| L1 合成 | 隔离输入的正反例、打包/解析等回归 | 硬件保护与实际写入有效 |
| L2 编译 | 固定源码、配置、工具链与产物哈希 | 手机可启动或安全 |
| L3 真机 | 授权、指定设备/变体、固件/镜像哈希和实测 | 其他变体或长期稳定 |

未运行不得写通过；来源报告和本项目证据分列。

## 红黄绿灯治理

统一含义：🟢 该项满足要求；🟡 预警并安排跟进；🔴 必须执行对应处置。同一维度取最高等级，各维度分别报告；红灯是否阻断合并由下表明确，不用单一总灯色覆盖其他维度。

| 维度 | 🟢 正常 | 🟡 预警 | 🔴 必须处置 | 动作与解除条件 |
| --- | --- | --- | --- | --- |
| PR 规模 | ≤5000 行且≤70 个文件 | 超过 5000 行或 70 个文件 | 超过 7000 行或 90 个文件 | 黄灯建议着手合并、收尾并停止扩展；红灯必须启动合并工作、停止扩展，后续开发另开 PR |
| PR 文件硬上限 | ≤100 个文件 | 无 | 超过 100 个文件 | 红灯阻断合并，须拆分；预计超限先拆分 |
| 单份自维护源码 | ≤300 行 | 301–600 行 | ≥601 行 | 黄灯在 TECH_DEBT 登记路径、责任工作包、保留原因与偿还条件；红灯阻断合并，必须按职责拆分，登记不豁免 |
| 文档预算 | 满足 [GOVERNANCE](GOVERNANCE.md#篇幅与读取) 预算 | 无 | 超出适用预算 | 红灯阻断合并，去重、压缩或归档，不提高预算或机械拆篇 |
| 合并验收 | 约定验证与复核通过 | 有归属的非阻断跟进项 | 必需证据不足、约定检查未通过，或违反安全、来源、授权要求 | 红灯阻断合并，补齐证据或修复后复核 |

PR 行数取 GitHub `additions`（全部新增行），文件数取 `changed_files`（全部变更文件）；创建或更新前结合本地预估，更新后复核。启动合并工作须在 PR 记录收尾、审查与验证待办；启动后可为这些工作超过行数红线，文件硬上限始终有效，其他阻断项不解除。启动收尾与绿灯均不等于授权合并，执行仍按 [AI_RULES](AI_RULES.md#pr-与合并)。

每项报告维度、灯色、实测值/证据、处置、责任与关闭条件；缺少证据标为“未验证”，不得标绿，若为必需门禁则按验收红灯处理。规模跟进写 PR，未知假设写 RISK_REGISTER，有意妥协写 TECH_DEBT；登记不替代修复与验证。灯色只适用于所列对象、HEAD/基线与证据范围，不能推为产品能力完成。

## 最低验证

| 改动 | 要求 |
| --- | --- |
| 文档 | 仓库检查脚本 + `git diff --check`；人工检查职责、链接与事实 |
| Python / Shell | 上述 + 相关离线正反例；ShellCheck 至少 error 级 |
| C / DTS / 固件 | 上述 + 目标 L2 编译；硬件行为另需适用 L3 |
| CI / 权限 / 治理门禁 | 适用回归；workflow 改动加 actionlint，远端结果另记 |

检查命令见 [CI](CI.md)。无 Git 时使用外部原始快照的 `git diff --no-index --check`，保留实际退出码与诊断，不冒充通常仓库检查。

## 源码篇幅门禁

- 自维护源码按物理行计数，包含空行、注释、许可证头和无末尾换行的最后一行；分级与动作统一见上表。
- 范围包括 C/C++/Rust/汇编、头文件与 `.inc`、Python/Shell/PowerShell、DTS/DTSI、Kconfig/Kbuild/Makefile（含 `.mk`）及 Dockerfile；测试、测试桩和本地改编驱动同样适用。新增语言须同步检查器范围及回归。
- 完整未修改的外部 Linux/UEFI 源码在 Git 外的 `.work/` 等约定工作区维护，不纳入篇幅统计；本地维护副本不得按来源豁免。生成产物不得入库；许可证正文、来源锁、配置/binding YAML 与历史日志不按源码计数，文档沿用 GOVERNANCE 预算。
- 禁止通过压缩代码、删除必要注释或任意编号文件绕过门禁；拆分须有职责、接口与真实调用关系，保留归属许可。有线供电状态机、锁、互锁及失败恢复须保持完整，无线 RX/TX 独立划界。
- `tools/check_repo.py` 全量检查已跟踪及未忽略新文件；源码红灯返回非零，黄灯打印待登记项且本身不使命令失败。登记完整性、职责合理性和拆分安全性由 Audit/专项复核检查；旧超限不设基线豁免，拆分后按实际行数重新分级。离线检查不覆盖 PR 规模或完整合并验收。

## Linux 接口验收

- 逐项记录锁定上游版本、子系统/UAPI/binding、Debian 消费方式与差异；依赖 Android HAL 或未登记私有 ABI 的功能不得标记为 Linux 产品能力完成。
- 验证属性单位、范围、读写权限、错误码、事件通知与设备发现；用标准用户空间入口验证成功、缺失/不支持及恢复路径，不只看节点存在。温度单位按各子系统定义，禁止混用 IIO/thermal 与 power_supply 标度。
- 新增/修改 DT binding 执行目标 `dt_binding_check`，板级 DTS 执行相关 `dtbs_check`；记录命令、schema 范围及诊断。旧例外须关联 TECH_DEBT，新引入错误阻断；dtc 或 L2 通过不能替代 schema 检查。
- 产品验收使用 Debian 的标准接口消费者；初期可用最小 Linux 测试程序取得单项证据，不能据此宣称 Debian 已集成。有线、无线 RX、无线 TX、NFC RF 与 eSE 分别验收；标准接口、上游合入与 L2/L3 证据独立记录。

## 审查与记录

低风险文案由开发者自查；普通工具需检查调用者/错误路径。固件、DTS、供电、启动/存储、CI/权限和治理门禁属于高风险，合并前须开发者以外专项复核、失败/恢复反例，以及适用 L2/L3 或明确的未覆盖阻断边界。不确定时从高。

结果记录环境、准确命令、退出码、未覆盖项，归档后由 CONTEXT 引用；真机字段使用 [模板](templates/hardware-evidence.md)。完成还须来源许可清楚、风险/债务有归属，合并流程见 [AI_RULES](AI_RULES.md)。
